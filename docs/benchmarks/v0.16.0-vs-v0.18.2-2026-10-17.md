## 1. Executive Summary & Scope

Between `v0.16.0` and `v0.18.2`, PeerHub progressed across 50 commits (PRs #103 through #111), categorized into nine functional clusters (`C1`–`C9`). The system advanced from an initial read-only inspection engine with bounded session reuse into a multi-group adaptive operational dashboard with model-fact provenance, central connection factory enforcement, and a breaking schema version gate (`user_version = 4`).

This document presents:
1. Complete feature evolution tracking from `CHANGELOG.md`, `docs/`, `git log v0.16.0..HEAD`, and the post-0.16.0 traceability ledger.
2. An empirical, side-by-side benchmark conducted across isolated virtual environments (`D:\PkgDev\_sys\data\temp\bench-*`) using real AI peers (`cx` / Codex, `cc` / Claude Code, `ag` / Antigravity). All live measurements strictly preserved repository integrity (`D:\PkgDev\workspace\peerhub\.peerhub` was copied into isolated temp workspaces and remained untouched).
3. Recursive MECE deconstructions (Category $\rightarrow$ Subcategory $\rightarrow$ Leaf) evaluating functional capabilities, execution efficiency, operational effectiveness, and version verdicts.

## 2. Core Feature Evolution (v0.16.0 to v0.18.2)

### 2.1 Release Baseline: v0.16.0 (2026-10-14)
- **Inspection & Diagnostics:** Read-only inspection commands (`peer list`, `stream list`, `profile list`, `session list`, `diag health`).
- **Session Reuse PR1–PR3:** Removed legacy `ask --resume`; introduced mutually exclusive `--fresh` and exact `--session <HANDLE>`. Mono-generational opaque session handles with monotonic sequence IDs, capped at 20 retained non-tombstoned sessions per stream/peer with a 30-day inactivity expiration.
- **Durable Replay & Identity:** Replay returns durable session snapshots; unstarted legacy selector mismatches reject deterministically.
- **Provider Resilience:** Confirmed process-tree termination on abort/timeout (stuck-streams PR 1, #95); bounded output drain-and-truncate (`output_truncated`) preventing process wedging (stuck-streams PR 2, #97); provider refusal classification (stuck-streams PR 3, #98).
- **Profile Consolidation:** Retired `*.pro` profiles; standardized on 9 profile targets (`{cc,cx,ag}.{standard,effort,deepthink}`).

### 2.2 Incremental Release: v0.16.1 (2026-10-16)
- **Monitoring Read Model:** Added SQLite-backed projections for sessions, delivery execution, usage, context, runtime provenance, capacity, coverage, and store health.
- **Quota Projections:** Typed quota projections and resource pool provenance (`probe:*`); context tracked with freshness invariants.
- **Telemetry Receipt Versioning:** Schema-versioned session telemetry receipts.

### 2.3 Incremental Release: v0.17.0 (2026-10-16, Candidate Draft)
- **Grouped Dashboard Default:** Bare `peerhub monitor` switched to watch grouped views in human and JSON modes. Introduced `peerhub monitor groups` catalog.
- **Coverage Detection:** Detected peers omitted by bounded scope samples, marking execution as partial.

### 2.4 Incremental Release: v0.18.0 (2026-10-16)
- **Visual Dashboard Formatting:** Aligned grouped visual dashboard on TTYs; clean delimited plain sections when redirected.
- **Machine JSON Contract:** `--json` defaulted to Schema 2.0; legacy Schema 1.1 explicitly preserved via `--schema-version 1.1`. Deprecated `--legacy` shim.

### 2.5 Incremental Release: v0.18.1 (2026-10-16, Candidate Draft)
- **Adaptive Terminal Geometry:** Dynamic resizing and responsive group omission based on terminal height/width (budgeting minimum 32 columns). Cached snapshot reuse on redraw.
- **Safe Read Context:** Added visible read-error context and refresh warnings in the terminal frame.

### 2.6 Current Release: v0.18.2 (2026-10-17)
- **Monitor Peers Dependency View:** Compact, dependency-linked block per peer linking quota $\rightarrow$ profile/model config $\rightarrow$ latest session reuse mode $\rightarrow$ context window.
- **Model-Fact Provenance:** Transparent footer disclosing profile revision, checked age, and source CLI observation commands.
- **Breaking Store Schema Gate v4:** Database schema bumped to `user_version = 4`. Older binaries refuse v4 stores via strict `future_schema_message` guards.
- **Central Connection Factory:** Core connections unified into one factory enforcing WAL, 30s `busy_timeout`, `foreign_keys = ON`, and `recursive_triggers = ON`.

## 5. Comprehensive Summary & Recommendations

1. **Performance Parity with Architectural Decoupling:** CLI startup and basic read operations remain swift (~0.35s–0.48s), with a slight +23ms startup regression in v0.18.2. Live provider asks continue to run at provider wire speed (4.5s–8.2s).
