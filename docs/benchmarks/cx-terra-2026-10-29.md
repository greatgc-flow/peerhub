# cx.terra (gpt-6.1-terra) quick benchmark, 2026-10-29

Purpose: decide whether the opt-in `cx.terra` profile deserves a packaged slot. Method: `codex exec`
0.165.0, read-only sandbox, prompt on stdin, 4 deterministic tasks (bugfix with hidden asserts,
counting 1..10000 divisible by 3 or 5 but not 15 = 4001, strict JSON with computed values, interval
merge with edge cases) x 2 repetitions per cell = 8 calls per config. Script and raw results:
[cx-terra-2026-10-29/](cx-terra-2026-10-29/).

| Config | Pass | bugfix | count | json | merge | Avg latency | Output tokens |
|---|---|---|---|---|---|---|---|
| gpt-6-luna / low (`cx.standard`) | 4/8 | 2 | 0 | 0 | 2 | 5.3 s | 351 |
| gpt-6.1-terra / low | 6/8 | 2 | 0 | 2 | 2 | 5.1 s | 401 |
| gpt-6.1-terra / medium | 8/8 | 2 | 2 | 2 | 2 | 5.8 s | 483 |
| gpt-6.1-sol / medium (`cx.effort`) | 8/8 | 2 | 2 | 2 | 2 | 9.9 s | 660 |

Reading (small and noisy: 4 easy tasks, n=2; one earlier invalid run passed `count` for terra/low 2/2,
so treat single cells as +-1): luna/low failed both arithmetic tasks in every run; terra/medium matched
sol/medium on accuracy with about 40% faster replies and 27% fewer output tokens; terra/low sits between
luna/low and terra/medium. Not measured: cost per token, quota burn, long-context or multi-file work.
Per-call input tokens (~14k, mostly the fixed codex prompt) are identical across models and not comparable.

Tentative: terra/medium is a candidate for `cx.effort` and terra/low for `cx.standard` if arithmetic
reliability matters more than the cheapest tier; no packaged change until cost/quota is known (pricing
research #259) and a larger run agrees. Opt-in stays in `~/.peerhub/config/models.toml`.

Pitfall found: on Windows, passing a multi-line prompt as an argument to `codex.cmd` truncates it at the
first newline (the model replied "Please paste the function"); pass the prompt on stdin (`-`).
