# PeerHub M1 Test Set — Recursive MECE Baseline

This directory is a **machine-readable test contract** for writing RED tests prior to implementation.

## Core SSOT
- `requirements.json` — **85 requirements** + required dimensions
- `test-catalog.json` — **207 concrete tests**
- `RECURSIVE_MECE_MODEL.json/.md` — Test space partitioning/exit criteria
- `STATE_MACHINE_COVERAGE.json` — State transition/prohibited transition coverage
- `EXCEPTION_CATALOG.json` — **85** exception/boundary/fault terminal dispositions
- `INTERACTION_MATRIX.json` — **34** high-risk cross-feature interactions

## Human-readable View
- `RED_SEQUENCE.md`
- Do not maintain requirement↔test tables as files: they are generated by `python -m tools.traceability`.

## Core Rules
1. A requirement is not complete just because it has one test.
2. The union of dimensions of linked tests must cover all `required_dimensions` of the requirement.
3. State transitions/exceptions/high-risk interactions are cross-verified again in separate inventories.
4. DEFERRED/OUT_OF_SCOPE are not permitted without rationale/triggers.
5. P0 required dimensions must have P0 deterministic evidence, excluding live.
6. META tests + package validators block drift in the test set itself.

Current baseline: **85 requirements / 207 tests / OPEN exception 0 / uncovered required interaction 0**.

## Release gate traceability

`TEST_RELEASE_GATE_MAP.json` assigns the 207 tests 1:1 to primary release gates. Gate dependencies are defined by `../../08_LIFECYCLE/release-gates.json`.
