# Retained sessions and durable ask results

PR1, PR2, and PR3 fresh/exact selection are committed (`12129517`), along
with health check fixes (`cfb28aba`). Recorded deterministic validation: 2,329 passed,
pyright 0 errors. Historical validation is recorded in the [PR2 scope review](PR2_SESSION_REUSE_VALIDATION.md)
and [PR3 gate-to-test matrix](PR3_SESSION_REUSE_VALIDATION.md).
The [Pre-TDD Renewal](../design/peerhub-pre-tdd-renewal-2026-10-14.md) and
[Debate Ledger](../design/peerhub-deepthink-debate-2026-10-14.md) define the proposed
bounded inspection, attributable telemetry, and recovery architecture.

Ordinary asks search retained compatible history at `(store, stream, peer)`.
Compatibility includes runtime kind, adapter fingerprint, effective binding and
workspace lineage. Native reuse additionally needs a vendor ID and trusted
consumed-prompt watermark. Custom local runtimes keep external-ID resolution and
delivery-evidence catch-up. Returning to an older local generation includes
intervening context; only responses provably generated by that exact local
session can be omitted. Native deltas conservatively include same-peer responses.
Overflow falls back only before possible execution; uncertain work blocks the
scope before any session selection.

`bridge_session_history` owns immutable handles (`sess_` plus 16 lowercase hex
digits), scoped generation/binding identity and mutable lifecycle/context facts.
`bridge_sessions` is an MRU pointer containing scope, handle, generation and
update time. All execution consumers resolve the actual delivery's generation;
completion, cancellation and loss never attribute execution to today's pointer.
`bridge_session_counters` preserves each scope's high-water mark, including
overwritten legacy generations proved by deliveries/events.

The writer retains at most 20 non-tombstoned rows per scope. More than 30 days
without completion expires a row; exactly 30 days remains eligible. Pruning,
events, eligible pointer repair and allocation commit under the claim fence.
Tombstones remain immutable audit rows, so this is not a total-table size cap.
Read-only diagnostics never perform expiry, repair or collection.

Migration runs atomically in the Bridge writer transaction, applying PR1's
permanent consumed-context proof before replacing an old slot. Known CLI
capability is corrected; custom capability remains unchanged. Unprovable native
continuity becomes LOST, while custom local resolution survives. A rollback
restores schema and data together; reopen does not mint another handle or append
historical call receipts. No temporary second session store remains.

New ask prompts persist normalized `session_selector` (`latest`, `fresh`, or
`sess:<full-handle>`) with their full scoped identity. Python accepts only
`fresh` and `session`; CLI exposes mutually exclusive `--fresh` / `--session`.
PR3 also records adapter fingerprint and workspace lineage in prompt identity.
Earlier prompts lacking these immutable proofs remain inspectable but cannot
be replayed through `ask` (`legacy_selector_unsupported`); no proof is invented.
Replay compares that identity before looking at a durable
result and returns its original session snapshot without constructing a Bridge,
reading the MRU pointer, checking current liveness or executing a provider.
Selector-less historical terminals remain inspectable as Records/evidence but
have no replay shim. Proven unstarted queued legacy prompts commit a rejection
result/evidence and Offset consumption together (`legacy_selector_unsupported`);
unresolved invocation markers, STARTED and MAY_HAVE_STARTED remain guarded.

Fresh selection always allocates with `reason="explicit_fresh"` and records
the deliberately unused prior handle; bounded Stream catch-up still applies.
Exact selection validates scope, expiry/state, capability and trusted native
continuity, workspace lineage, fingerprint, effective binding and delta budget.
Custom local sessions retain external-ID resolution without a native watermark.
Known failures and overflow are checked before a new prompt is appended where
provable, and queued intent is revalidated under its claim fence. Expiry commits
before rejection. Exact resolution failures never allocate a substitute.
Definitive NOT_STARTED rejection commits result, evidence and Offset progress
together; storage faults, stale fences and open invocation markers remain errors
or uncertain work. Rejected requests replay their durable error without execution.

Delivery snapshots bind handle, generation, accepted mode/reason and prior
handle before invocation. They become immutable at the invocation marker and
remain unchanged on recovery. Terminal results carry that snapshot. Exactly one
`session_call` receipt accompanies the first confirmed STARTED transition;
counter increments and receipt insertion share the same fenced transaction.
Exactly one terminal `session_telemetry` receipt accompanies durable completion
or provider refusal. Replay, repeated STARTED, duplicate terminal callbacks and
recovery add no duplicate receipt. MAY_HAVE_STARTED alone creates no call.

`bridge_session_monitor_stats` and `bridge_session_monitor_scope` hold lifetime
counts, completeness, evidence pointers and effective creation binding metadata.
Only unambiguous recorded modes reconstruct legacy totals. Unknown totals stay
null after new calls; tombstoning does not subtract lifetime counts. Late
unattributable STARTED confirmation invalidates totals instead of fabricating a
mode. Scope coverage records the migration evidence high-water mark. The quota
writer also installs the bounded subject/kind/pool/time index for future readers.

JSON always includes `session` and `error`. Successful results have `error=null`;
pre-allocation failures have `session=null`; later failures carry the actual
accepted session. For example:

```json
{"session":{"handle":"sess_0000000000000001","generation":1,"mode":"fresh","reason":"no_prior","prior_handle":null,"telemetry":{"last_input_tokens":null,"context_window":null,"context_pct":null,"source":"unknown","quota":null}},"error":null}
```

Text output ends with exactly one newline-terminated stdout trailer after
allocation, including on error or replay:

```text
session: sess_0000000000000001 fresh gen1 reason=no_prior
session: sess_0000000000000001 resumed gen1
session: sess_0000000000000002 fresh gen2 fallback reason=binding_change
```

Context occupancy and quota snapshots remain unknown in PR2. Billing `usage`
stays separate and is never converted into occupancy. Ask does not probe quota.
`peerhub session list/show` now provide read-only inspection. List defaults to
20 rows and uses keyset pagination bound to database identity, workspace
generation, filters, ordering, and first-page row high-water. Both commands
expose PeerHub handles and redacted state only; vendor and external session IDs
are never included. The CLI opens an existing database in read-only mode and
does not initialize bridge tables. Grouped monitoring uses a shared read-only
snapshot with bounded session, usage, context, runtime, and coverage projections;
unsupported context occupancy remains unknown. See
[monitoring](../../README.md#everyday-commands) for current commands.
