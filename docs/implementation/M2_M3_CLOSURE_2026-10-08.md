# M2/M3 Contract Closure Record — 2026-10-08

This document records the decisions, rationale, evidence, rejected proposals, and remaining limitations that closed outstanding items in
`CONTINUITY_COLLABORATION_AUDIT.md`, `MCP_PORT_AUDIT.md`, `MEMORY_SEARCH_AUDIT.md` (the former `REMAINING_WORK_*` trackers were retired once the backlog was empty). It is implementation evidence, not a frozen contract revision or promotion to VERIFIED.

## Principles (ToGo 09_ROADMAP: M2/M3 Pre-TDD Review)
Core remains Peer/Stream/Record/Offset and does not import extensions · Records are authoritative; projections can be rebuilt ·
UNKNOWN does not mean healthy/unlimited/0 · MAY_HAVE_STARTED prohibits blind replay · Unsupported AI judgments are not truth ·
No Extension→Extension implementation imports (composition belongs in `peerhub/cli`) · Very Simple (no solver, daemon, marketplace, or raw shell) ·
Compatibility/migration from previous releases is not considered (M2/M3 have never been released).

## Independent Code Reviews (ag·cx) Incorporated
After implementation, ag and cx independently reviewed 4 areas in read-only mode. All reproduced defects were confirmed in code and fixed (8 A2A defects: duplicate submission, false remote absence, stale not_started, terminal state overwrites, response identity bypass, error code coercion, endpoint substitution, missing overall deadline · discarding results completed just before the deadline · Host boot cascades/entrypoint/broken manifests · Work/Skill/Capability creation wedged by crashes · Eval tampering during evaluation · lost Memory quarantine policy · Artifact GC grace-period criteria and shard parent sync · Skill digest races with file changes · weak tests).
**Unchanged after review**: (1) The race between the pre-restore idle check and swap — restore assumes offline operation, replaces live state, and discards derived DBs, so the check is a safety net rather than a fence. (2) The claim that "an intent marker left after a completed swap reverts the new DB" is false — recovery rolls back only if the workspace directory is absent; otherwise, it only removes the marker (`test_a_stale_intent_marker_after_a_completed_swap_never_reverts_the_restored_workspace`).

## Stated Limitations
- **A2A**: The HTTP binding was validated with an in-process server implementing the same JSON-RPC subset. **Official SDK server validation results are recorded in the interoperability check below; other third-party servers remain unverified.** Private/link-local HTTPS destinations are allowed (general SSRF isolation is outside this binding's scope).
- **Cost**: Checks occur between attempts, so a single attempt (up to `max_fanout` in-flight attempts in parallel) can exceed the budget.
- **Parallel execution** is opt-in; callers are responsible for runner thread-safety.
- **ProcessRuntimeAdapter** assumes trusted argv (failure isolation and cancellation, not a security sandbox). Python plugins also run in-process.
- Tests requiring Windows long-path behavior and symlink permissions could not be run on this host.
- MAY_HAVE_STARTED retries for steps declared `idempotent=True` are allowed only in execution without a journal (the explicit declaration is treated as evidence). Durable execution always requires reconciliation.
- **A2A interoperability check (2026-10-08, after v0.12.1):** `tools/a2a_sdk_interop.py` validated the official `a2a-sdk` 1.2.2 server for A2A 1.0 JSON-RPC `SendMessage`, `GetTask`, `CancelTask`, reconciliation through `messageId` in history, and `TASK_NOT_FOUND`. The HTTP binding uses `SendMessage`/`GetTask`/`CancelTask`, `TASK_STATE_*`, and `A2A-Version: 1.0`. The server assigns the task id; the local task id is sent as `message.messageId`. If the `SendMessage` response is lost, lookup by local id is unavailable, so an operator must provide a candidate remote id to `reconcile_task(task_id, remote_task_id=None)`; it is adopted only if the remote history contains the local `messageId`. With no candidate id, no history, or no match, `A2AExecutionUncertainError` preserves the uncertain state; if unresolved, `abandon_task` permanently retires the local id. HTTP `TASK_NOT_FOUND` also does not guarantee absence and does not release the id. When a pending task was cancelled with `CancelTask`, the adapter returned `CANCELLED` and the remote state was `TASK_STATE_CANCELED`. Other third-party servers remain unverified. Direct Message responses and streaming are unsupported and fail closed.
