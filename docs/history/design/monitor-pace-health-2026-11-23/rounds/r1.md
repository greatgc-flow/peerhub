* **WHY:** Having three vocabularies (compact `ok/fast`, expand `ON_PACE/THREAT`, diag `spend/hold/rest`) violates SSOT; unified state words plus parent-clamped forecasts prevent agents/humans from over-allocating to a child pool whose parent is about to exhaust.
* **REJECTED:** Adding a sparkline or burn-rate history column, which requires a time-series query and adds visual noise without changing the action decision.
* **COMPACT/EXPAND:** Yes; both use the lowercase 7-char-max state enum (`spend`, `ok`, `fast`, `rest`, `out`, `clamped`) from the shared planner function.
* **AI SURFACE:** Yes; `diag --plan` and `monitor` call the exact same `classify_pool(pool, parent)` function.
* **COST:** ~40 LOC.

### CROSS-CUTTING
1. **Unified Pool Evaluator (SSOT):** D2, D3, D4, D5, and D9 all collapse into one pure function `evaluate_pool(reading, parent_reading, config) -> PoolView` shared by `monitor` (compact & expand) and `diag --plan` (text & JSON).
2. **Width Budget Resolution:** Combining `PACE(=EVEN)` (D1), `RESET/EXH` (D4), and `FAMILY/PROFILES` (D5) eliminates all three omitted columns in `--expand` (`exhaust-in`, `age` lives in header, `profiles`) while keeping compact and expand under 80 columns.
3. **Missing Item — Stale Data Gating:** When `quota age > TTL (300s)` or a refresh fails, `PACE` and `EXH` can mislead; `STATE` should append `?` (e.g. `ok?`) in both compact/expand and set `stale: true` in `diag --plan --json`.

### RISKS
* **OSC 8 width calculation (D7, D8):** `len(line)` counts raw escape bytes unless ANSI/OSC-8 sequences are stripped before padding; must use a visible-length helper (`vis_len()`) or right-alignment and table columns will misalign.
* **Zero/tiny elapsed division in `EXH` (D4):** Immediately after a pool reset (`elapsed < 1%`), point burn rate spikes wildly; lock `exh` to `>7d` until `elapsed >= 2%` or `used >= 5%`.
