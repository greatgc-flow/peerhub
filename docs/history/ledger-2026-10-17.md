### 2.2 `docs/design/plan-monitoring-v2-2026-10-12.md` (Monitoring v2 Specification)
- **Accepted / Shipped Decisions:**
  - **NO_COLOR standard:** Respect no-color.org. Empty `NO_COLOR=""` is ignored; non-empty disables color. `FORCE_COLOR` or `CLICOLOR_FORCE` overrides `CLICOLOR=0`. Plain text and JSON remain strictly escape-free. Windows VT enabled via `ctypes` (`0x0004`) with cursor restore (`\x1b[?25h`).
  - **Exit code table:** 0 OK, 1 ALERT (returned ONLY when status is clean/OK, never masks failures), 2 USAGE, 4 FAILED/PARTIAL (including `PROBE_FAULT`), 5 UNAVAILABLE, 6 SCHEMA_VERSION.
  - **Collection cadence:** Monotonic interval scheduling defaulting to 60s (`--interval-seconds 60`), 30s timeouts, and exponential failure backoff (120s, 240s, capped at 900s).
  - **Staleness policy:** Fresh <300s, Stale >=300s, Expired = frame time >= reset. Latest probe errors reported distinctly from stored capacity.
  - **Agy token guard:** Suspends `ag` collection immediately if model token consumption is detected or unverifiable, unless `--allow-agy-token-use` is passed.
  - **Privacy allowlist:** Strict schema allowlist on exports (zero prompts, zero completions, zero raw CLI payloads, zero paths, zero credit/account IDs).
  - **Pace balance engine (Rule R1):** Evaluates $cc.\text{pace} \le \min(ag.\text{3P}, ag.\text{G})$ and $|\max(ag.\text{3P}, ag.\text{G}) - cx.\text{pace}| \le 5\text{ pt}$. Reports factual `'lowest 7d pace: <peer/pool>'` without subjective routing recommendations.
  - **Single-line summary (`--line`):** Concise formatted ASCII status for shell/AI integration.
  - **Flag cleanups:** Removed `monitor --once` (superseded by `peerhub diag`); stripped terminal control escape artifacts (`\x1b[H\x1b[2J`).
- **Rejected Attempts:**
  - Removing `diag --live` and replacing it with `monitor --read-only`: REJECTED. `diag --live` remains the canonical read-only committed-evidence watcher; `monitor` composes collection with the shared dashboard.
  - 1-hour recent-rate burst forecasting in runtime: REJECTED from product runtime; restricted to offline backtesting (`tools/quota_backtest.py`).
  - Background daemons, webhook listeners, desktop notification popups, audio bells: REJECTED as non-goals.
  - Automatic database history pruning: REJECTED without an explicit, reviewed migration.
  - Subjective peer recommendation (`prefer X`): REJECTED in favor of factual lowest-pace display.
- **Deferred Attempts:**
  - Offline forecasting candidate promotion: DEFERRED pending >=30 windows, >=10 exhausted / >=10 quiet, >=80% precision/recall, and empirical uncertainty intervals.
  - Long-term SQLite growth pruning: DEFERRED to a future reviewed migration.

### 2.3 `docs/design/plan-session-monitoring-2026-10-13.md` (Session Monitoring Pre-TDD Spec)
- **Accepted / Shipped Decisions:**
  - **Read-only invariant:** Pinned transaction with `mode=ro` and `query_only=True`; zero subprocess execution and zero SQLite writes during inspection.
  - **Session handle standard:** Random opaque handle `sess_[0-9a-f]{16}` (64 bits entropy).
  - **Call counting semantics:** Lifetime counts include confirmed STARTED deliveries (including subsequent errors/cancellations); unconfirmed or NOT_STARTED deliveries excluded.
  - **Separation of concerns:** Writer projections atomically store immutable evidence (`bridge_evidence`); readers render shared snapshot structures without on-the-fly aggregation loops.
- **Rejected Attempts:**
  - Speculative historical count backfilling: REJECTED. Missing historical data remains explicitly null/UNKNOWN.
  - Separate `monitor --read-only` flag: REJECTED (duplicates `diag --live`).
  - Storing or displaying vendor conversation IDs, prompt/completion text, or secrets in monitoring views: REJECTED.
  - Mutating schema migration during read-only inspection: REJECTED. Read-only commands fail fast on unsupported schema versions.
- **Deferred Attempts:**
  - Whole-store active totals across all history: DEFERRED in favor of bounded MRU scopes (20 streams per peer) to guarantee bounded query execution.
  - Context occupancy percentage for `cc`/`ag`: DEFERRED (retained as null/UNKNOWN) until attributable runtime vendor reports are implemented.
  - Interactive terminal keystroke controls (`a` ack, `q` quit): DEFERRED.

### 2.4 `docs/design/plan-session-reuse-2026-10-13.md` (Session Continuity & Retained Reuse)
- **Accepted / Shipped Decisions (PR1–PR3 in v0.16.0, v0.18.2):**
  - **Static capability vs. per-call preference separation (PR1):** Adapter capability (`ProviderSpec.can_resume = True` for `cx`, `cc`, `ag`) separated from caller flags. Removed caller-preference `resume` flag across CLI/API/metadata.
  - **Retained session registry (PR2):** Implemented `bridge_sessions` (latest pointer per stream/peer), `bridge_session_history` (append-only historical session generations), and `bridge_session_counters` (monotonic generation allocator).
  - **Random opaque handles (PR2):** Generated via `secrets.token_hex(8)` (`sess_[0-9a-f]{16}`). Zero metadata leakage.
  - **Sequential generation numbering (PR2):** Monotonically increasing `session_generation` per `(stream_id, peer_id)`.
  - **Bounded retention & tombstoning (PR2):** Bounded history keeping $N$ latest sessions (default 20) and max age (30 days); tombstones older generations.
  - **Explicit addressing via `--session <handle>` and `--fresh` (PR3):** Strict validation of stream, peer, workspace, and binding. Fails fast on any mismatch; never falls back silently.
  - **Sequential identity contract (PR3):** Resuming a session mutates the live vendor thread in place; does not rewind workspace files or model parameters.
  - **Corrected catch-up delta (PR1–PR3):** Resumed sessions receive all stream records beyond their `context_watermark`, including intervening responses from the same peer.
  - **Structured output & trailers (PR2–PR3):** Always emits `session` in JSON stdout (or null on error); text mode appends exactly one trailer.
- **Legacy Mining Findings & Dropped Capabilities (§2.3, §2.4):**
  - **Dropped legacy CLI flags:** `--session-policy <auto|reuse|fresh>`, `--session-id <id>`, `--room-id <room>` dropped without shims.
  - **Dropped over-engineered abstractions:** Dropped `SessionLeaseCoordinator`, `SessionBindingKey`, `UnitOfWork` revision CAS loops, and 9-state enum sets in favor of clean SQLite transactions and a 4-state lifecycle (`FRESH`, `ACTIVE`, `LOST`, `TOMBSTONED`).
  - **Dropped v0 schema migration shims:** Core schema version gate strictly rejects pre-v1 stores.
  - **Prohibited caller-supplied arbitrary session IDs:** Prohibited to eliminate collisions and vendor ID leakage.
  - **Prohibited permission inheritance:** Writable permissions (`--writable`) must be explicitly passed on each invocation; never inherited.
  - **Prohibited untargeted thread inspection:** Rejected legacy `ORDER BY updated_at DESC LIMIT 1` pattern; require exact thread ID binding.
  - **Prohibited silent fallback:** Automatic fallback after a `STARTED` delivery or on explicit `--session <handle>` is strictly forbidden.
- **Deferred Attempts:**
  - Session forking / branching: DEFERRED (requires vendor `--fork-session`).
  - Cross-stream session reuse: DEFERRED (violates stream boundary).
  - Concurrent resumes on the same session: DEFERRED (single-flight enforced by claim fence).
  - Unbounded session history retention: DEFERRED.

### 2.5 `docs/design/peerhub-session-usage-monitoring-review-2026-10-15.md` (Session Usage Review)
- **Accepted / Shipped Decisions (v0.18.0–v0.18.2):**
  - **Single-receipt authority:** Exactly one versioned `bridge_evidence.kind=session_telemetry` receipt (schema version 3); no parallel facts database tables approved.
  - **Non-billing observational stance:** Reports observable durable session state, recent execution health, context evidence, and account quota without financial billing, cost estimation, or automated routing.
  - **Exclusion of speculative metrics:** Monetary cost, cross-provider token averages, and cumulative session token differencing are excluded.
  - **Attribution & provider scope:** Provider counters treated as unattributed when cumulative; never differenced into fake per-delivery deltas.
  - **Bounded scope query optimization:** Grouped scope reader uses indexed recursive successor seeks (capped at 21 scopes per peer before joining), eliminating full-table window ranking scans.
  - **Capacity group with single-sample pace:** Reads latest quota/rate-limit observations; computes 7-day pace ($used\% - elapsed\%$) from a single fresh weekly sample.
  - **Runtime provenance separation:** Session binding values recorded as immutable generation snapshots; current profile configuration is separately labeled `current_config` and never backfilled.
  - **Scale benchmark acceptance:** Established `monitor_frame_scale_v1` fixture (5,000 retained sessions, 50,000 deliveries, 24 pools, 100,000 unrelated rows); verified local warmed p95 <=150ms (achieved 27.4ms on reference host).
- **Rejected Attempts:**
  - Parallel facts or telemetry database tables: REJECTED (preserves single `bridge_evidence` receipt authority).
  - Deriving context occupancy from token usage counters: REJECTED.
  - Two-sample delta for 7-day PACE: REJECTED as design drift; pace is strictly single-observation deviation from uniform elapsed time.
  - Spawning provider CLI processes during monitor reads: REJECTED (zero subprocesses during monitor reads).
  - Backfilling current configuration edits into historical session provenance: REJECTED.
  - Zero-filling missing metrics: REJECTED; missing values remain explicit null/UNKNOWN.
- **Deferred Attempts:**
  - Context window occupancy measurement for Claude/Agy: DEFERRED / remains UNKNOWN until reliable vendor subprocess reporting is wired.
  - Normalized per-turn token delta accumulation: DEFERRED until providers expose validated event-scope telemetry.
  - Step-level telemetry summaries: DEFERRED from initial view.
  - Automated quota-based traffic steering: DEFERRED / out-of-scope.
