# REL-005 exact pytest execution oracle (2026-10-16)

## Problem and scope

The release gate's REL-005 test currently counts the developer-environment collection and expects that many passes from a credential-free, network-blocked run. On Windows the suite correctly skips one POSIX-only PTY test, so the count-based oracle rejects a successful run. Replace that inference with an exact collected-node and per-phase outcome oracle. This is test infrastructure only: it does not change product behavior, suite targets, release gate ordering, or the provider/network isolation guarantee.

Keep v0.18.1 as a draft and leave its tag untouched. Once the fix merges, prepare v0.18.2 as a distinct release candidate, run its required G3/G4/publish gates, and publish only after all required checks pass. The already generated `docs/implementation/live_evidence/2026-10-16.json` is local release evidence, not a source change; do not include it in the implementation or version-bump commits. The test-only PR has no version bump. The subsequent release-preparation PR alone updates version, changelog, and status.

## Invocation parity and plugin loading

Use one checked-in, test-only pytest plugin at `tests/_rel005_oracle.py`; do not add it to `src/`, extension inventories, or runtime packages. Both the developer collection and sandbox execution invoke the same `sys.executable -m pytest`, repository checkout, explicit `pyproject.toml` config, root directory, target list (`tests/communication/architecture`, `tests/communication/e2e`, and `tests/communication/fault/test_flt_bridge.py`), marker expression, and flags (`-q`, `-p no:cacheprovider`, `-p no:xdist`, and `-p _rel005_oracle`). Explicitly remove `PYTEST_ADDOPTS` in both environments. Pass the same live/soak opt-in variable values in both environments (all unset/false); the explicit marker expression is `not slow and not e2e and not live and not canary and not soak`, which overrides the configured `addopts` marker expression.

The plugin module lives directly under `tests/` so it is importable by its stable top-level name. Set `PYTHONPATH` explicitly for both runs to the same `<site-dir><sep><repo>/tests` value, avoiding dependence on pytest startup ordering; cwd is `<repo>`. Construct `_no_provider_env` once and use the same provider-free filtered environment, reduced `PATH`, and socket-blocking `sitecustomize.py` for both runs so environment-sensitive collection cannot drift. This preserves network blocking and exposes only the intended plugin path. Assert the plugin's report was written in both runs; plugin import failure or missing/invalid report is a hard gate failure.

The only invocation differences are `--collect-only` on the developer run versus execution on the second run, and each run's unique report destination/nonce. Both use exactly the same environment, resolved interpreter, pytest version, flags, config, and targets. The plugin records `pytest.__version__`; validation requires matching versions. Since `pyproject.toml` supports `pytest>=8.0`, compatibility tests must exercise both the 8.0 lower bound and the current resolved CI version (currently verified locally with pytest 9.1.1). CI records the resolved version; a dependency or resolver change triggers these compatibility checks before release.

## Evidence format and validation

Create fresh unique collection/execution temporary directories for each parent test invocation; pass report destination and nonce as explicit plugin command-line options (not environment variables), and have the plugin echo/check the per-run nonce. The plugin records the pytest version, collection item nodeids in order, every collector report's nodeid/type/outcome (collector reports are not test items), the exact `pytest_deselected` nodeids/count, and each `pytest_runtest_logreport` nodeid/phase/outcome, exact skip reason, and xfail marker. `pytest_collectreport` outcomes must all be passed; duplicate collector `(nodeid,type)` reports fail, and collector reports are never compared as item nodeids. Only the `session.items` list is the item set. At session finish it records pytest's exit status and writes JSON atomically: write a sibling temporary file, flush/close it, then replace the destination. A partial or stale file must never be accepted as evidence.

The pure validator rejects malformed evidence, nonce/version mismatch, nonzero subprocess or pytest exit, duplicate item nodeids, collection-list mismatch, duplicate collector `(nodeid,type)` reports, any collector report other than passed, missing reports, and any nodeid mismatch between developer collection and sandbox execution. Require identical deselected nodeid lists/counts in the two runs and record them in the report. Do not recollect during execution validation: compare the developer collection to the exact `session.items` list captured by the sandbox plugin in that same execution.

For each normally executed item, require exactly this ordered lifecycle: `setup/pass`, `call/pass`, `teardown/pass`; reject `wasxfail`, xfail, xpass, skip, failure, error, duplicate, absent, or reordered phase reports. On POSIX, the observed skip-nodeid set must equal the empty set. On Windows, it must equal exactly `{tests/communication/e2e/test_cli_monitor.py::test_posix_pty_snapshot_obeys_physical_viewport}`. That test must have exactly `setup/skipped` followed by `teardown/passed`, with no call phase. Extract the reason only from pytest's structured `(path, line, reason)` tuple and compare the third field exactly without normalization; unknown representations fail closed. The reason in the Windows marker is `POSIX PTY smoke; Windows TTY behavior is covered by ConPTY/manual tests`. An actual pytest 9.1.1 hook probe showed that `report.longrepr[2]` is the exact raw string `Skipped: POSIX PTY smoke; Windows TTY behavior is covered by ConPTY/manual tests`; the validator must compare that raw representation, including the prefix. The pytest 8.0.0 compatibility probe must confirm the same raw value, and any version-specific change fails closed until explicitly reviewed.

Negative validator tests cover omitted/added/duplicate nodeids; collection mismatch, duplicate/failed/skipped collector reports; deselection mismatch; unexpected, missing, wrong-node, wrong-reason, and wrong-phase skip; xfail/xpass; missing/duplicate/reordered test phases; teardown failure after call pass; nonzero exit; malformed/incomplete/stale-nonce evidence; and pytest version mismatch. Positive cases cover all-pass POSIX and the one exact Windows PTY skip. Run the hook-contract tests with pytest 8.0 and 9.1.1, report the actual version in CI, and require an explicit compatibility test when the pytest dependency changes.
