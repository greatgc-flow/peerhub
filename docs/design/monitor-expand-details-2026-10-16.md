# Height-adaptive monitor detail rows (2026-10-16)

## Evidence and scope

The responsive TTY renderer plans additional detail rows from available height, but `peerhub/cli/monitor_view.py::_group_lines` truncates sessions, usage, context, runtime and capacity observations to two items before layout. Reproduction on the explicit workspace database:

```powershell
python -m peerhub --db .peerhub/core.db monitor --snapshot --group all --json
```

In the local workspace at review time, a captured snapshot had `sessions.data.items=100`, `sessions.data.sample_size=100`, `sessions.data.truncated=true`, and `capacity.data.observations=9`. The renderer showed the first two records in unbounded text and `+98 sessions not shown`; those 98 are records already loaded into the renderer, not missing telemetry. Feeding that same snapshot to the pure bounded planner at width 80 rendered one session detail row in a 24-row viewport and two in a 60-row viewport; the 60-row frame used only 36 of its allowed 59 rows. This was a local snapshot-backed pure-render measurement, not a live TTY capture, and is not reproducible from the commit because the workspace database is intentionally not included. Treat it as diagnostic observation, not an acceptance artifact. The deterministic fixture below is the reproducible evidence. Source truncation at the 100-session cap is a separate, real coverage limit.

Fix the presentation boundary only. Keep the schema-2 snapshot, SQLite queries, provider calls, JSON contract, selected group catalog/defaults, and terminal I/O architecture unchanged. Do not add paging, input mode, dependencies, migrations, or a second rendering system. This is limited to the five existing record-detail groups: sessions, usage, context, runtime, and capacity. It does not change the independent peer and execution-scope caps in overview/execution. The bounded interactive TTY expands those five groups from the cached snapshot. The unbounded `height=None` and redirected renderers retain their existing layout and two-record summary; their `+N ... not shown` line describes renderer-hidden rows, while source coverage remains separately represented. This is no viewport-height omission and preserves the existing full-frame/redirected-output contract.

## Intended behavior

- The pure TTY layout receives the same cached immutable snapshot and current geometry. It renders every candidate record already present in that snapshot until the viewport budget is exhausted; resize/countdown reflow performs no database or provider reads.
- In bounded TTY mode, preserve one required summary line after each visible group heading. For non-empty record-detail groups, the aggregate replaces the current first record row as the bounded-mode summary; it does not add a row or displace the summary budget. Detail records follow that summary. For empty record-detail groups, retain the established semantic text (sessions `Retained sessions: 0`, usage `Provider-reported usage: unknown`, context `Runtime context occupancy: unknown`, capacity `Quota capacity: no observations`, runtime `Runtime profile provenance: no sessions`) and append the source-state suffix at every width; do not render a zero-count aggregate. At width 80, preserve the full established text before the suffix. At narrower widths, shorten/drop the semantic text before the source suffix using the same priority and narrow-code rules as non-empty summaries. If no source evidence exists, append canonical `UNKNOWN` as unreported, not complete. If `data` is unavailable (`null`), preserve `data unavailable` as the summary, use `UNKNOWN`, and emit no aggregate or details. For `ERROR`/`FAILED` groups, preserve the existing sanitized error reason as the summary, use `UNKNOWN`, and emit no aggregate or details. Keep any distinct explicit coverage supplemental row for an empty group; suppress only the sessions/capacity generic row when it repeats the exact own-group source state. Other groups keep their existing summary/detail meaning.
- Keep a single pure presentation source: refactor `_group_lines` into a helper that returns structured group content (`summary`, ordered candidate detail rows, the exact legacy `height=None` rows, loaded count, source-completeness state, and any non-record supplemental rows). The bounded planner uses full candidate rows, determines visible rows first, then formats aggregate summary counts. The `height=None`/redirected adapter must emit only the existing legacy rows (first two detail records and existing `+N ... not shown` remainder, or existing empty-state row), with no aggregate line; preserve its current output byte-for-byte. Both adapters consume the same extracted snapshot facts and detail formatter, so compatibility does not require a second data or presentation source. Terminal I/O remains in `monitor.py`/`view.py`.
- Aggregate facts come only from the passed snapshot: `loaded` is the length of the group's existing record list; `visible` is the number of those records actually rendered as detail rows; `off-screen = loaded - visible`. Use group-specific labels (`session records`, `usage scopes`, `context scopes`, `runtime sessions`, `quota observations`). Do not infer total retained history from a sample length.
- Source completeness is independent of renderer visibility. For sessions, use the group's explicit boolean `data.truncated` (`true` = partial, `false` = complete); missing or non-boolean means unknown. For capacity, use its own explicit boolean `data.truncated` with the same predicate; missing or non-boolean means unknown. Usage/context/runtime are projections of the session cohort: when the sessions group is included, report the parent's explicit state as derived via partial/complete sample; when sessions is absent or its state is unknown, report canonical `UNKNOWN` (meaning source truncation unreported). Never infer truncation from row count.
- Summary strings are count-first and fit by display-cell width, with source state taking precedence over counts. `width` means the terminal `columns` argument; a frame line is bounded to `columns - 1`, then the existing two-cell content indent is reserved, so the summary cell budget is `C = max(0, width - 3)`. Use canonical states `PARTIAL`, `COMPLETE`, `UNKNOWN`, `VIA PARTIAL`, and `VIA COMPLETE`. For own-group evidence map partial/complete/unknown to `PARTIAL`/`COMPLETE`/`UNKNOWN`; for usage/context/runtime derived from an included sessions group map its partial/complete state to `VIA PARTIAL`/`VIA COMPLETE`; if sessions is absent or unknown, use `UNKNOWN` (the canonical short form for unreported source truncation). Suffixes by outer width are: >=48: `source partial|complete|unknown|via partial|via complete`; 32–47: `SRC PARTIAL|COMPLETE|UNKNOWN|VIA PARTIAL|VIA COMPLETE`; 9–31: `SRC P|C|U|VP|VC`. For outer widths 5–8, use the corresponding bare status code `P|C|U|VP|VC`. At outer width 4 (`C=1`), use one-cell codes `P|C|U|p|c`, where uppercase is own-group partial/complete/unknown and lowercase `p/c` means via partial/complete. Publish the legend `P=own partial, C=own complete, U=source state unknown, VP=derived via partial sessions, VC=derived via complete sessions` in monitor group-catalog help and user documentation; lowercase `p/c` are their width-4 counterparts. At widths 1–3, no source-summary cell fits within the physical `columns - 1` bound; omit the record-detail summary only because no content cell is physically renderable. Keep the title/frame within the physical bound.

- Build the longest count prefix that fits before the already-selected suffix: at outer width >=48 try `N loaded · V visible · R off-screen · <suffix>`, then `V/N shown · +R · <suffix>`, then `V/N · <suffix>`, then the suffix alone. At widths 32–47 try `V/N shown · +R · <suffix>`, then `V/N · <suffix>`, then suffix alone. At widths 9–31 try `V/N · <suffix>`, then suffix alone. At widths 5–8 use only the bare status code, dropping all counts. At width 4 use the one-cell own/derived codes above, dropping all counts and semantic empty text. Never pass a string that omits or truncates the source suffix to `_fit`; reserve its full display-cell width first and fit/drop counts or empty-summary text before it. If `C` is narrower than the selected `SRC ...` suffix, use the corresponding bare code. At widths 1–3, omit record-detail summaries because no source-status cell can fit inside the physical bound. Apply existing safe-text and `_fit` rules to remaining text. The loaded count, status, summary meaning, and order remain stable as only visible/off-screen counts change. Summary/status lines remain before details and participate in existing severity-based group selection.
- Allocate optional details in deterministic round-robin passes over visible groups in their current summary/catalog order. Each pass emits at most one next detail row per group, preventing a session-heavy group from starving capacity/runtime. After allocation, render each group's assigned detail rows contiguously in the same visible summary/catalog order, prefixed with its group label (for example, `SESSIONS · ag ACTIVE ...`) so interleaving allocation does not make rows ambiguous. Prefix cells count toward the physical line width and are reserved before fitting the detail payload; shorten the payload first, never the identifying group prefix. If the full prefix plus the minimum safe payload cannot fit within `columns - 1`, omit that detail row and leave its summary visible. Reserve all retained non-record supplemental rows (including usage provider-scope telemetry coverage) and AGY continuation/refresh warning rows before optional detail allocation; these rows consume the available row budget and round-robin begins only after they are emitted. Preserve severity ranking and exact omitted-group guidance when group summaries do not fit.
- A detail row omitted because its required prefix and minimum safe payload do not fit consumes that group's slot for the current round-robin pass. Do not retry the same group in that pass; proceed to the next group, and consider its next candidate on the next pass. This keeps allocation deterministic and prevents an unrenderable candidate from changing another group's turn order. Record-fit checks use terminal display-cell width against `columns - 1`, including the exact group prefix; tests cover both a fitting row and an over-width row in the same pass.
- A taller viewport must reveal more records until either the row budget or the candidate sample is exhausted. Keep physical `rows - 1`/`columns - 1` bounds, selected-group priority, title/database provenance, compact-mode safety, and cached reflow behavior intact.
- Non-TTY `--snapshot`, redirected text, plain output, and JSON contracts remain unchanged. Snapshot remainder wording continues to mean renderer-hidden rows; source truncation is separately surfaced through coverage. `peerhub monitor --group sessions` continues to allocate the viewport to session detail.

## Contract amendment and sequencing

The previously approved responsive-rendering contract says spare rows are spent on details in the same order as visible summaries. This design explicitly amends that allocation rule: preserve that group order, but allocate one row per group per pass (round-robin) before any group gets a second row. The change is justified by the observed 100-session cohort starving other visible data groups and is limited to bounded TTY detail allocation. Group summary order, severity selection, and unbounded/redirected output remain unchanged. This amendment requires unanimous CC/CX/AG approval before implementation. The actual output's `+98 sessions not shown` line is accepted for `height=None`: it counts loaded rows suppressed by the legacy renderer cap, while source truncation at 100 is separately shown. In bounded mode, suppress the redundant generic `Coverage: partial · sample truncated` row only for sessions/capacity when the appended own-group suffix is any own-partial form at that width (`source partial`, `SRC PARTIAL`, `SRC P`, bare `P`, including width-4 `P`). For derived usage/context/runtime groups, retain all supplemental coverage information; in particular, usage's provider-scope telemetry row is distinct and is reserved before optional detail allocation. The exact allocation fixture leaves `coverage_by_scope` empty and removes only the redundant sessions partial row. For empty sessions/capacity groups, apply the same own-state duplicate suppression after the suffix is appended; retain any distinct coverage evidence. The unbounded adapter retains all legacy coverage rows byte-for-byte. The bounded aggregate summaries intentionally apply only to interactive bounded TTY layout; the unbounded adapter keeps the exact legacy row set, so no byte-compatibility claim conflicts with adding a bounded summary.

Use a named deterministic fixture helper, `tests/communication/diag/test_monitor_view.py::_detail_expansion_payload()`, to create 100 anonymized session records and 9 capacity observations. This fixture is the reproducible evidence; no live TTY capture is required or claimed. It must assert exact load/visibility/off-screen values at both 80x24 and 80x60 and independent session-source truncation. Empty record groups keep their established useful unknown/zero summaries: `Retained sessions: 0`, `Provider-reported usage: unknown`, `Runtime context occupancy: unknown`, `Quota capacity: no observations`, and `Runtime profile provenance: no sessions`.
