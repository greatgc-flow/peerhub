## 3. Investigated Issues & Fixes Applied

### 3.1. Middle-Dot Separator (`·` -> `?` in Windows Terminal / CP949 / Plain Mode)

- **Symptom:** In Windows terminals (e.g., CP949 on Korean Windows), redirected output, or `--view plain`, `peerhub monitor --snapshot` and `monitor` dashboard frames printed `?` in place of the middle-dot separator `·` (e.g., `Coverage: partial ? sample truncated`, `1.50s avg ? 2 samples`, `ag ACTIVE ? gen 1 ? resumable`, `Schema 4 ? database 1.0 KiB`).
- **Root Cause:**
  1. In `peerhub/cli/monitor.py:104`, `unicode_ok` checks `view != "plain" and (sys.stdout.encoding or "").lower().startswith("utf")`.
  2. On non-UTF consoles (CP949, CP1252, etc.) or when piped/plain, `unicode_ok` evaluates to `False`. While CP949 can represent `·` (`\xa1\xa4`), it cannot represent Unicode box-drawing (`│`, `─`) or block characters (`█`, `░`), so disabling rich borders was correct.
  3. However, `peerhub/cli/monitor_view.py` unconditionally hardcoded `·` in all line templates, and then executed `line.encode("ascii", errors="replace").decode("ascii")` when `unicode=False`. Because `·` is non-ASCII (`\u00b7`), `encode("ascii", errors="replace")` replaced every `·` with `'?'`.
- **Fix (TDD):**
  - Updated `monitor_view.py` to use dynamic delimiters based on the `unicode` parameter: `sep = " · " if unicode else " | "` and `dot = "·" if unicode else "|"`.
  - In `_render_unbounded_frame` and `render_grouped_frame`, safely sanitize any remaining `·` into ` | ` or `|` before ASCII conversion when `not unicode`.
  - Added unit test `test_plain_ascii_monitor_replaces_middle_dot_cleanly_without_question_marks` in `tests/communication/diag/test_monitor_view.py`.
- **Verdict:** Fixed and verified. All separator instances in plain/CP949 modes now cleanly render as ` | ` without any `?` artifacts.

### 3.2. Missing Store JSON Reporting Parity

- **Symptom:** Running `peerhub --db <nonexistent> peer list --format json` printed an error message to `stderr` and returned exit code 5, but emitted nothing on `stdout`. In contrast, `session list --format json`, `monitor --snapshot --json`, and `diag health` emitted structured JSON: `{"status": "UNAVAILABLE", "error": "database not found: <path>"}`.
- **Root Cause:** `peerhub/cli/app.py:902` called `report_missing_store(args.db)` for core read commands without passing `json_output`.
- **Fix (TDD):**
  - Passed `json_output=bool(getattr(args, "format", None) == "json" or getattr(args, "json", False))` at `app.py:902`.
  - Added test `test_core_read_missing_store_emits_json_when_requested` in `tests/communication/e2e/test_cli_contract.py`.
- **Verdict:** Fixed and verified. Core read commands now emit structured UNAVAILABLE JSON on stdout when JSON formatting is requested.

## 4. Findings Left-As-Is (with Rationale)

| Finding | Current Behavior | Rationale for Leaving As-Is |
| :--- | :--- | :--- |
| **Output Flag Inconsistency** (`--format` vs `--json`) | Core (`peer`, `stream`, `profile`, `session`) uses `--format {auto,table,json}`; Extensions (`ask`, `monitor`, `diag`) use `--json`. | Historical convention across M1/M2/M3 boundary. Changing flag names would break external scripts, wrappers, and CI automation. |
| **Command Verb Asymmetry** | `record read` vs `record list`; `stream show` vs `peer get`. | Established CLI schema in `app.py`. Renaming or aliasing subcommands requires deprecation cycles and documentation shifts; unnecessary for a safe CLI sweep. |
| **Absence of `stream close` CLI subcommand** | Streams are finalized via Core API or session transitions; no standalone CLI subcommand. | PeerHub streams are append-only storage logs. Adding a mutate CLI command requires design validation and tests; beyond minimal sweep scope. |
| **Exit Code 1 vs 2 on Validation** | CLI flag errors return 2 (standard `argparse`); domain errors return 1 (or 2 for `ask` invalid arguments). | Strictly complies with POSIX argparse conventions and existing exit code contracts in `CONTRIBUTING.md`. |
| **Console Encoding Policy** (REL-002 / REL-011) | `peerhub/_console.py` reconfigures `errors="replace"` but does not force UTF-8 on the stream. | Explicit project design decision: PeerHub never forces an encoding on the user's terminal to prevent pipeline breakage or locale conflicts. |
