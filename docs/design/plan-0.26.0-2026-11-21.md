## 1. Where paths exist

- `--query-file` lives in the CLI namespace. The CLI opens it relative to the **ask process cwd**, decodes and normalizes the bytes, then passes only the prompt string and the separate `--workspace` option to `ask()`. `ask()` stores the prompt as a Record body. `--stream` is a SQLite Stream ID, defaulting to a peer chat or a request-specific ID for stateless peers. `peerhub/cli/app.py:199`, `:400`, `:430`; `peerhub/extensions/ask.py:108`, `:181`, `:296`.
- Normal ask output flows through subprocess pipes and a bounded in-memory buffer. The terminal result and response are durable in SQLite. The retained session has an opaque vendor ID and binding, with no transcript path. There is no normal per-ask file under `.peerhub`. Batch is an exception for prompt **input**. It writes a child query file in a temporary directory and removes it when the batch exits. `peerhub/extensions/adapters/process.py:197`, `:237`; `peerhub/extensions/bridge.py:1497`, `:1652`; `peerhub/extensions/bridge_registry.py:16`; `peerhub/extensions/batch.py:339`, `:418`.
- `ProcessRuntimeAdapter` has a separate capability-job stdout spool, `peerhub-job-*.out`. Its path is local to `_procs` and gets unlinked on observed settlement or confirmed cancel. Normal asks use the CLI/API targets. Monitor opens the selected DB read-only, reads committed rows and never receives ask memory. Its existing Claude transcript reader is for interactive leads. **UNVERIFIED** which real file #417 calls `stream_file`. The supported ask flow supplies no such path. `peerhub/extensions/runtime_port.py:399`, `:427`, `:432`, `:491`; `peerhub/extensions/ask.py:175`; `peerhub/extensions/monitor_read_model.py:1085`, `:1100`, `:1606`; `peerhub/extensions/lead_sessions.py:100`, `:261`.

## 2. Existing per-ask metadata and time

- `bridge_evidence.detail` for `kind='caller'` stores `cwd`, host and process identity per delivery, before invocation. `cwd` is the CLI's cwd, possibly truncated. The provider cwd is set from `--workspace` or cwd and hashed into the CLI binding. `bridge_session_history.workspace_generation` is a lineage token. `peerhub/extensions/caller.py:56`, `:82`; `peerhub/extensions/bridge.py:560`; `peerhub/extensions/ask.py:175`; `peerhub/extensions/adapters/base.py:1300`; `peerhub/extensions/bridge_registry.py:16`.
- `bridge_sessions.updated_at` is the session pointer time. History has `last_seen`, refreshed at terminal commit. The ask heartbeat extends `bridge_claims.expires_at` by `lease_sec`. For an active matching generation, `expires_at - lease_sec` gives acquisition or last heartbeat time. Release sets expiry to now. Use `bridge_deliveries.terminal_at` for an exact finish. `peerhub/extensions/bridge_registry.py:12`, `:56`; `peerhub/extensions/bridge.py:1497`, `:1521`; `peerhub/extensions/bridge_claims.py:50`, `:155`; `peerhub/extensions/monitor_read_model.py:748`.
- Cheapest shared storage is optional keys in existing caller JSON. Monitor already selects the latest caller detail and accepts extra v1 keys. Two nullable `TEXT` columns on `bridge_deliveries` could use the existing `PRAGMA`/`ALTER TABLE` migration, but would add a write and old-schema read handling. Prompt metadata is checked on replay. Terminal result JSON arrives too late for RUNNING. `peerhub/extensions/monitor_read_model.py:431`, `:614`; `peerhub/extensions/bridge_registry.py:196`; `peerhub/extensions/ask.py:184`; `peerhub/extensions/bridge.py:1497`.

## Decisions

- **D1 · #417.** Put nullable `query_file` and `stream_file` in caller evidence when the actual path is available, with the resolved execution workspace for eligibility. Resolve query input from the ask cwd. Omit unsafe paths at write time and revalidate from the monitor before linking. Leave `stream_file` null until there is a concrete, ask-owned source. An ordinary `--stream` ID, a vendor transcript guess and the capability-job spool yield no link. Keep caller evidence outside replay identity. Use a private human-render input for paths so public JSON gains no path exposure.
- **D2 · #417.** Use OSC 8 `file://` links for existing local regular files inside the recorded workspace, on the originating host. Resolve symlinks and junctions. Reject escapes, UNC/device paths and control characters, including in resolved paths. Encode the URI with `Path.as_uri()` and truncate its label before wrapping. Honor the Guide's rich/color/VT, `NO_COLOR`, `PEERHUB_NO_LINKS` and TTY gates plus `PEERHUB_MONITOR_TEXT=off`. No file generation or TUI. `peerhub/cli/monitor.py:252`, `:446`; `peerhub/cli/monitor_view.py:2794`, `:2807`.
- **D3 · #406.** Ship vote A. Keep certainty, status, exit code, denial names and JSON fields. No automatic retry, prompt rewrite or partial-result contract.
- **D4 · #419.** Move the two runtime scratch allocators. Amendment A1: batch uses `<db.parent>/tmp` (or `<db.parent>/.peerhub/tmp` when the DB is not inside `.peerhub`); the runtime port takes an explicit `scratch_dir` from its owner and keeps today's system-TEMP default when none is given, with cleanup on settle, cancel and orderly exit either way. Preserve destination-local atomic stages. Clean owned scratch on normal exit, interruption and failures where child termination is confirmed. No global temp override or cleanup sweep.
- **D5 · #418.** Use the exact-SHA CI handoff and retain artifact smoke. Move only the duplicate source matrix and its reports. Record the CI run URL with the release evidence. Parallelism and timeout tuning stay outside this release.
- **D6 · #415.** Keep prompt-cache TTL in backlog. Revisit when ≥20% of same-stream gaps are 5–60 min, cache-read/write ≥2.0, and cc PACE is below both cx and ag. [Backlog trigger](https://github.com/greatgc-flow/peerhub/issues/415)

- **D7 · #420.** Deferred to 0.27.0 as its own release (vote 2026-11-21: scope too large with four fixes; the ATTN badge would need a persisted check result, a new store). Design kept in #420: read-only `peerhub update --check` and `--plan`, no auto kill/install, resume hints from existing rows. No code in 0.26.0.
