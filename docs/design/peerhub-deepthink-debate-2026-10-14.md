## 3. Explicit Concessions, Retractions, and Dissent Register

### ag Concessions & Retractions
1. **Retraction on Output Cap Invariance (A-D06):** Retracted initial position treating existing `--max-output-bytes` as verify-only. Endorsed 3-budget model (protocol drain under deadline, parsed answer cap, debug tail).
2. **Retraction on Blocked Delivery Deferral (A-D03):** Retracted deferring stream resolution. Earlier blocked-delivery counts were not tied to a reproducible query in the review artifacts and are not used as proof of urgency; the blocking failure mode and owner priority support including audited recovery.
3. **Correction on Context Window Invariants (A-D14):** Conceded that 475,000 tokens observed in a local rollout is an empirical sample, not a universal provider constant.
4. **Concession on Keyset Pagination (A-D17):** Adopted cx's immutable sequence keyset `(stream_id, peer_id, session_generation DESC, session_handle DESC)` over mutable timestamp ordering.

### cx Concessions & Retractions
1. **Correction on schema compatibility (not a concession to v2):** Earlier synthesis incorrectly proposed version 2. Source and tag v0.15.2 both support 3; the revised proposal is 4 with one-connection migration and an actual old-executable refusal gate. cx's earlier textual agreement to v2 is superseded by this verified fact and is not treated as assent to v4.
2. **Retraction on Replay Configuration Coupling (X-D10):** Retracted requirement that replay must match current runtime configuration, adopting decoupled caller-intent comparison on `(stream, peer, request_id)`.
3. **Retraction on Alert Baseline Dependency (X-D01):** Conceded that session inspection must not depend on MV2 quota alert policies.

### cc Retractions & Refinements (Round 4 Review)
1. **Retracted "Process exit is always terminal" (C-3):** Process exit proves process death only; no automatic retry. Confirmed `STARTED` certainty is preserved.
2. **Retracted "Handle-only uncertainty (scope never blocked)" (C-5):** Blocking the stream offset at uncertain prompts is justified. Resolving via `stream resolve` unblocks subsequent asks with `prior_abandoned`.
3. **Retracted "All-null unless window known" & "Prohibit >100%" (C-2):** Measured tokens survive independently; ratios $>100\%$ are stored unclamped and labelled `ratio_anomaly`.
4. **Refined SHA & DB Stance:** Build-time SHA stamping without runtime git calls; separate dev DB is a useful convention, not an automated safety barrier.
