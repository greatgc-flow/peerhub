**Scope:** Phase 0 behavioral-fixture evidence. This document is additive and does not rewrite historical records.

## 2. Non-goals and invariants

This plan MUST NOT:

- relabel `LEGACY_CAPTURE` or `V1_SPEC_ONLY` as `V1_CAPTURE`;
- alter fixture status overlays, legacy captures, Hub state, provider state, or routing configuration;
- include `AC-*` in any Phase 0 behavioral completion count; or
- authorize a live-provider invocation, broker implementation, or cutover.

Any future promotion is a separate governed decision and requires fresh evidence generated by the authorized controlled-fake runner or a later approved harness. Existing legacy bytes may be indexed and verified; they MUST NOT be re-stamped as a fresh V1 execution.

## 3. Evidence index contract

The future index is a mapping from fixture IDs to explicitly enumerated artifacts. It is not inferred from filename globbing, timestamps, or model names.

Each index record MUST include:

| Field | Requirement |
|---|---|
| `index_id` | Stable identifier, unique within the index. |
| `fixture_ids` | Non-empty explicit behavioral IDs covered by this record. |
| `evidence_class` | One of `LEGACY_PAYLOAD`, `LEGACY_TRANSCRIPT`, `LEGACY_SHARED_TRANSCRIPT`, `V1_CAPTURE` only when separately authorized. |
| `artifacts[]` | Repository-relative path, role (`payload`, `transcript`, `receipt`, or `log`), `raw_bytes_sha256`, and byte size. |
| `coverage` | For shared material, every covered fixture ID plus the deterministic selector used to associate it with that ID. A selector may be a named case key when the artifact has named cases; otherwise it is `UNSPECIFIED_LEGACY` and cannot support V1 promotion. |
| `validation` | `raw_bytes_verified`, `schema_observed` (string or `null`), `v1_capture_asserted`, and `phase0_exit_eligible`. An index validator MUST reject `evidence_class: V1_CAPTURE` unless the record carries a separate, hash-bound promotion-ratification ID. |
| `baseline_binding` | Declared baseline revision/digest values observed in the source, if present; absent values remain absent rather than guessed. |

All legacy index records MUST set `v1_capture_asserted: false` and `phase0_exit_eligible: false`.

Example shape (illustrative, not an added index record):

```json
{
  "index_id": "IDX-LEGACY-DP-02-03-TRANSCRIPT",
  "fixture_ids": ["DP-02", "DP-03"],
  "evidence_class": "LEGACY_SHARED_TRANSCRIPT",
  "artifacts": [{
    "path": "docs/design/phase0/fixtures/captures/DP-02-03.transcript.json",
    "role": "transcript",
    "raw_bytes_sha256": "d77be372e8ea6ff2206fe663c7152ff585f0a6a5b2f982a78e74140576f1d7cd",
    "bytes": 861
  }],
  "coverage": {
    "DP-02": {"selector": "covered_cases.spawned_false"},
    "DP-03": {"selector": "covered_cases.spawned_true"}
  },
  "validation": {
    "raw_bytes_verified": true,
    "schema_observed": null,
    "v1_capture_asserted": false,
    "phase0_exit_eligible": false
  }
}
```

## 4. Verification order

1. Resolve an index record by exact fixture ID; reject unlisted IDs and any `AC-*` ID in the behavioral index.
2. Resolve each repository-relative path beneath the approved captures root. Reject absolute paths, traversal, alternate data streams, and reparse-point escapes.
3. Verify the recorded SHA-256 against the raw bytes before parsing or normalizing any content.
4. Parse only after raw verification. Treat missing `$schema`, differing input shapes, nullable blockers, and different exit-code encodings as legacy variation, not automatic failure.
5. For a shared artifact, verify that every listed fixture has an explicit selector. A shared legacy transcript may prove legacy coverage only; it is strictly non-promotable and cannot satisfy a `V1_CAPTURE` requirement.
6. Report status separately for raw integrity, legacy coverage, V1 conformance, and exit eligibility. A pass in an earlier column MUST NOT imply a pass in a later one.

## 5. Future V1 promotion predicates

The following are requirements for a later promotion specification, not actions authorized by this plan.

- A new execution receipt MUST bind one behavioral fixture ID to the exact runner and baseline revision used.
- Its raw artifacts MUST have verified `raw_bytes_sha256` digests. If a future contract also uses a normalized or canonical digest, it MUST name the exact transformation, input scope, and algorithm; this plan does not choose one.
- It MUST validate against the frozen V1 error and certainty semantics, or reference a separately ratified divergence entry.
- It MUST preserve the 54/9 namespace separation and state whether the result is behavioral evidence or authority-cutover evidence.
- It MUST record a single-fixture provenance path. A shared legacy transcript may remain historical context, but cannot by itself establish a fresh per-fixture V1 execution.

## 6. Open decisions deliberately retained

- The exact V1 index file format and schema location.
- The canonicalization method, if any, for structured JSON beyond raw-byte verification.
- The authoritative baseline file list and invalidation mechanism.
- Whether named legacy-case selectors are sufficient for comparison-only reports.
- The ratified divergence-register format and the governing round for any promotion.

These decisions remain open so this evidence plan cannot silently create runner, schema, or cutover authority.
