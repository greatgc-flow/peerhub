## Wave 4 (control / context continuity)
- Q-W4-1 (no control machine in STATE_MACHINE_COVERAGE.json): the catalog has Stream/Offset/BridgeClaim/ExecutionCertainty/SessionGeneration/ObservationFreshness only. Defined two machines and tested allowed AND forbidden edges: ControlIntent (ACCEPTED -> APPLIED with a write-once outcome; forbidden: outcome rewrite, delete, identity change, second row for the same Record/peer, INSERT OR REPLACE) and Gating (paused = latest pause/resume by Record POSITION, never by handling order; cancel is a fence, not a pause). Confirm or amend the coverage JSON.
- Q-W4-2 (pending controls, replaces D-W3-7 interim): control Records are applied from the unread window before any session/runtime side effect (and re-checked before session resolution and before the invoke marker), then consumed by the Offset when the cursor reaches them (never prompts, never blocking). Pause gates delivery (`paused`, nothing runs, Offset untouched) until a later resume by position. Cancel = terminate intent + unread Records positioned BEFORE the cancel are skipped with `cancelled_skip` evidence (forward Offset only, nothing deleted); Records after the cancel run normally; resume does not undo a cancel. Spec only says "cancel intent commits before terminate/kill" and CTL-003 "Offset unchanged by controls"; the skip semantic is ours. Confirm.
- Q-W4-3 (authority): control Records authored by the bridged peer are rejected; a control without `targets` addresses every other member; `handle_control` resolves the peer from the persisted Record only when unambiguous (else `peer_id` is required and re-validated: member, not author, in targets). Unknown `control.*` kinds are recorded with outcome `unsupported_kind` and consumed.
- Q-W4-4 (runtime effects): effect (interrupt/terminate/steer) is only attempted for a delivery that may be running (MAY_HAVE_STARTED/STARTED, unacked); otherwise outcome `nothing_running` (no call). Missing capability -> outcome `unsupported` (never `done`); RuntimeTargetError -> `failed` (evidence, no retry, intent kept); other exceptions propagate and the TD-19 lease lets a later handler complete. Crash after the effect but before the outcome => effect re-issued once (at-least-once; interrupt/terminate are idempotent best-effort). Confirm acceptable.
- Q-W4-5 (CatchUpBudget, TD-12): record/byte/token budget; byte size = canonical JSON of {position, record_id, author_peer_id, kind, body} items joined by ","; tokens via an injected estimator; result = longest contiguous ordered SUFFIX (an oversized newest Record yields an empty truncated projection rather than a gap). The Bridge projects `(0, record.position)` (history before the Offset too, because a fresh session knows nothing), whereas CTX-001 says "after Offset": the function supports `after_position`, tested; the Bridge default is 0. Default Bridge budget = `catch_up_limit` records (100).
- Q-W4-6 (context.boundary Records): written by the bridged peer once per session generation > 1 (idempotency key `context-boundary:<peer>:<gen>`, body = reason + boundary metadata incl. truncation); a retry for a different Record keeps the first one. A context.boundary authored by someone else is outcome `noted`. Confirm kind/body shape.
- Q-W4-7 (redirect): same-goal redirect = `control.redirect` Record in the same Stream; delivered as `steer` only to a running session; otherwise handed ONCE as extra catch_up to the resumed session (and included in any fresh-generation projection). Goal identity = `Stream.metadata["goal"]` exact equality; a new goal needs an explicit `new_stream_id`, carries `metadata.prior_stream_id`, closes the old Stream by default (`close_prior=False` keeps it OPEN), first Record is a plain message. Confirm.
- Q-W4-8 (context loss signal): adapter-reported `ContextLostError` (subclass of PrespawnError) is accepted as an explicit pre-run report (NOT_STARTED, mapping LOST, retry on a fresh generation with catch-up; same trust as D-W3-8). After start evidence it stays STARTED/uncertain and the mapping is marked LOST.
- Q-W4-9 (precedence): `paused` is reported before `blocked_uncertain`; an explicit reconcile retry ignores the cancel fence (a later explicit authorization wins; ordering between reconcile and cancel by position is not modelled).
- Bug found by the new tests (fixed): a crash between fresh-generation creation and delivery lost the catch-up on retry (the old rule looked at the last session event); rule is now "no delivery has reached this generation".
